## 1. 目的

URLを1つ入力するだけで、そのサイト内でたどれるページをすべて自動で巡回し、各ページのスクリーンショットを撮る。
撮った画像はローカルの画面で一覧・比較し、デザインレビューに使う。

## 2. 前提

| 項目 | 内容 |
|---|---|
| 利用者 | 自分だけ（1人） |
| 対象サイトの規模 | 主に数十ページ程度（コーポレートサイトやLP中心のサイト） |
| 動作環境 | macOS（ローカルPCのみ） |
| 画面の形 | ローカルWeb UI（`http://localhost:xxxx` をブラウザで開いて操作する） |
| 外部サービス | 使わない。画像も設定もすべてローカルに保存する |

## 3. 利用シーン

1. **サイト全体の撮影**: トップページのURLを入れ、サイト全ページのスクリーンショットをまとめて撮る
2. **デザインレビュー**: 撮った画像をサイトの階層構造に沿って一覧で見て、気になるページを拡大して確認する
3. **比較**: 2回分の撮影結果（例: リニューアル前後、自社サイトと他社サイト）を並べて見比べる
4. **ログインが必要なサイト**: 会員ページや管理画面など、ログインした状態でしか見られないページも撮る
5. **JavaScriptで描画されるサイト**: Notionの公開ページやReact・Vueなどで作られたSPAのように、HTMLを読み込んだ時点では中身がなく、JavaScriptで画面を組み立てるページも、表示しきった状態で撮る

## 4. 機能要件

### 4.1 クロール（ページの収集）

| ID | 要件 | 優先度 |
|---|---|---|
| C-01 | 起点のURLを1つ入力すると、ページ内のリンク（`<a href>`）をたどって同じサイト内のページを自動で集める | 必須 |
| C-02 | 巡回の範囲は起点と同じホストとする。外部サイトへのリンクはたどらない。サブドメイン（例: `www.example.com` から `shop.example.com`）も含めるかは撮影ごとに選べる（初期値: 含めない） | 必須 |
| C-03 | 同じページを2回撮らない。URL末尾の `#…` は無視し、`/` の有無などの表記ゆれもまとめる | 必須 |
| C-03a | パラメータだけが違うURL（例: `?page=2`、`?id=123`）の扱いを撮影ごとに選べる。「別ページとして撮る」か「パラメータを無視して1枚だけ撮る」（初期値: 無視する） | 必須 |
| C-03b | 同じ階層にあるページ（例: `/blog/*`、`/products/*`）を撮影ごとに「全部撮る」か「先頭N件だけ撮る」から選べる（初期値: 全部撮る。N の初期値は 3） | 必須 |
| C-04 | 撮影する最大ページ数を設定できる（初期値 200） | 必須 |
| C-05 | 起点からの最大階層（リンクを何回たどるか）を設定できる（初期値 制限なし） | 推奨 |
| C-06 | 除外するURLのパターンを指定できる（例: `/blog/page/*`、`?sort=`） | 推奨 |
| C-07 | `sitemap.xml` があれば、そこに載っているURLも巡回の対象に加える | 推奨 |
| C-08 | JavaScriptで描画されるリンク（SPAなど）も拾えるよう、ページを実際にブラウザで表示してからリンクを集める。詳細は 4.5 を参照 | 必須 |
| C-09 | ログアウトや削除など、押すと状態が変わるリンクはたどらない（URLに `logout`、`signout`、`delete` を含むものを初期値で除外する） | 必須 |
| C-10 | PDFや画像など、HTML以外へのリンクは撮影対象にしない | 必須 |
| C-11 | 同じサーバーに負荷をかけすぎないよう、同時に開くページ数とアクセス間隔を設定できる（初期値: 同時に2ページ、間隔0.5秒） | 必須 |

### 4.2 撮影

| ID | 要件 | 優先度 |
|---|---|---|
| S-01 | 各ページを縦にスクロールした全体まで1枚の画像として撮る（フルページ撮影） | 必須 |
| S-02 | 画面幅を複数選べる。初期値は PC 1440px／スマホ 375px。任意の幅も追加できる | 必須 |
| S-03 | 画像はPNGで保存する | 必須 |
| S-04 | ページを読み込んでから撮るまでの待ち時間を設定できる（初期値 1秒）。画像の遅延読み込みに対応するため、撮影前にページ末尾まで一度スクロールする | 必須 |
| S-05 | Cookie同意バナーやチャットウィジェットなど、指定したCSSセレクタの要素を隠してから撮る | 推奨 |
| S-06 | アニメーションを止めてから撮る（CSSアニメーション・トランジションを無効にする） | 推奨 |
| S-07 | 1ページの撮影に失敗しても全体は止めず、失敗したページとその理由を記録する | 必須 |
| S-08 | 失敗したページだけを撮り直せる | 推奨 |

### 4.3 ログイン

| ID | 要件 | 優先度 |
|---|---|---|
| L-01 | 「ログイン用ブラウザを開く」ボタンで実際のブラウザ画面を開き、利用者が手でログインする。ログイン後の状態（Cookieなど）を保存し、クロールと撮影に使う | 必須 |
| L-02 | アプリはパスワードを入力・保存しない。保存するのはログイン後のセッション情報だけとする | 必須 |
| L-03 | 保存したログイン状態はサイトごとに名前をつけて管理し、削除できる | 推奨 |
| L-04 | Basic認証（ステージング環境などのID・パスワード入力ダイアログ）に対応する | 推奨 |

### 4.4 閲覧・比較（Web UI）

| ID | 要件 | 優先度 |
|---|---|---|
| V-01 | 撮影の進み具合（見つけたページ数・撮影済み・失敗）をリアルタイムで表示する。途中で止められる | 必須 |
| V-02 | 撮影結果をサムネイルの一覧で表示する。URLの階層（`/about/` 配下など）でまとめて表示できる | 必須 |
| V-03 | サムネイルを選ぶと原寸で表示する。画面幅ごとに切り替えられる | 必須 |
| V-04 | 過去の撮影結果を「撮影セッション」として一覧で残し、あとから開ける | 必須 |
| V-05 | 2つの撮影セッションを選び、同じパスのページを左右に並べて比較できる。左右のスクロールは連動させる | 必須 |
| V-05a | 比較画面で2枚を重ねて表示できる。重ねる方法は「半透明で重ねる（透明度を調整できる）」と「スライダーで境目を動かして切り替える」の2つ | 必須 |
| V-05b | 比較するページの組み合わせはパスで自動的に決める。片方にしかないページは「追加」「削除」として一覧で分かるようにする | 推奨 |
| V-06 | 撮影セッション単位で画像をまとめてフォルダに書き出す（ZIP） | 推奨 |
| V-07 | ページタイトル・URL・ステータスコードの一覧をCSVで書き出す | 任意 |

### 4.5 JavaScriptで描画されるページへの対応（SPA・Notionなど）

SPAやNotionのページには、通常のWebページとは違う次の特徴がある。

- HTMLを読み込んだ直後は中身が空で、JavaScriptが動いてから画面ができる
- ページ全体ではなく、ページ内の一部の領域（例: Notionの本文エリア）だけがスクロールする。このため通常のフルページ撮影では、最初に見えている範囲しか写らない
- 画面に入った部分だけを描画する作りのため、スクロールしないと下のほうの中身が作られない
- ページの移動が、ページの再読み込みなしにJavaScriptで行われる

これに対応するため、以下を満たす。

| ID | 要件 | 優先度 |
|---|---|---|
| J-01 | 「描画が落ち着いたか」を判断してから撮る。判断の材料は、通信が止まったこと、画面の要素の変化が一定時間（初期値 1秒）止まったこと、Webフォントと画像の読み込みが終わったこと。最大待ち時間（初期値 15秒）を超えたら、その時点の状態で撮り、ログに「待ちきれずに撮影」と記録する | 必須 |
| J-02 | 指定したCSSセレクタの要素が表示されるまで待ってから撮れる（例: Notionなら本文のブロック）。サイトごとに設定できる | 推奨 |
| J-03 | ページ内の一部の領域だけがスクロールするページでも、その領域の中身を最後まで1枚に収めて撮る。スクロールしている領域は自動で見つける。見つからない場合や誤る場合に備え、CSSセレクタで手動指定もできる | 必須 |
| J-04 | 画面に入った部分だけ描画するページに対応するため、撮影前にスクロール領域を末尾までゆっくりスクロールし、中身をすべて作らせてから撮る | 必須 |
| J-05 | 縦に非常に長いページ（目安: 高さ 15,000px 超）は、分割して撮ってから1枚につなげる。つなげられない場合は分割した画像のまま保存する | 推奨 |
| J-06 | リンク集めでは、`<a href>` に加えて、JavaScriptによるページ移動（History API）で生まれるURLも拾う | 推奨 |
| J-07 | 撮影前に実行するJavaScriptをサイトごとに登録できる（例: Notionのトグルをすべて開く、ポップアップを閉じる） | 推奨 |
| J-08 | よく使うサイト向けの設定をプリセットとして用意する。最初はNotionの公開ページ（`*.notion.site`）用を用意し、本文領域の指定、表示完了を判断する要素、隠す要素（「Notionで開く」などのバナー）を入れておく | 推奨 |
| J-09 | Notionのトグル（折りたたみ）を開いて撮るか、閉じたまま撮るかを撮影ごとに選べる（初期値: 閉じたまま） | 任意 |

Notionの非公開ページ（ログインしないと見られないページ）は、ログイン機能（L-01）を使って撮る。

## 5. 非機能要件

| 項目 | 内容 |
|---|---|
| 性能 | 50ページ・2つの画面幅（計100枚）で、おおむね10分以内に終わる。SPAやNotionのページは描画完了の待ち（J-01）とスクロール（J-04）があるため、1ページあたり最大20秒程度かかってよい 。ただし、アクセス制限の厳しいサイト（Notion など）は間隔を空けて巡回する必要があるため、この目安の対象外とする（50ページで30分程度。M0 の検証結果による） |
| 保存先 | 初期値は `~/SiteCapture/<ドメイン>/<撮影日時>/` 。設定で変えられる |
| ファイル名 | `<パスを_でつないだ文字列>__<画面幅>.png`（例: `about_company__1440.png`、トップは `index__375.png`） |
| 安定性 | 1つのページで固まっても、ページごとのタイムアウト（初期値 30秒）で次へ進む |
| セキュリティ | Web UIは自分のPC（127.0.0.1）からのみアクセスできるようにする。ログイン情報は保存先フォルダ以外に置かない |
| 礼儀 | `robots.txt` の扱いは設定で選べる（初期値は「従う」）。自社サイト以外を巡回する場合は利用規約に注意する |

## 6. 技術方針（案）

| 層 | 採用案 | 理由 |
|---|---|---|
| 撮影・巡回 | Playwright（Chromium） | フルページ撮影、画面幅の指定、ログイン状態の保存（storageState）、要素の非表示が標準でできる |
| サーバー | Node.js（TypeScript） | Playwrightと同じ言語で書ける |
| 画面 | ブラウザで開くWeb UI（React など） | 一覧表示や比較画面を作りやすい |
| データ保存 | 画像はファイル、ページ一覧や撮影履歴はSQLite（またはJSON） | 外部のデータベースを用意しなくてよい |

## 7. 対象外（今回は作らない）

- 定期的な自動撮影
- 画像の差分を自動で検出する機能（ビジュアルリグレッションテスト）
- クラウドへのアップロードや他人との共有
- フォーム送信やボタン操作をしないと出てこないページの撮影（ただし、同じページ内のトグルを開く、ポップアップを閉じるといった操作は、撮影前に実行するJavaScript（J-07）で対応する）
- Windowsでの動作保証

## 8. 決定事項の記録

| # | 論点 | 決定 | 反映先 |
|---|---|---|---|
| 1 | サブドメインも巡回するか | 撮影ごとに選べるようにする（初期値: 含めない） | C-02 |
| 2 | パラメータだけが違うURLの扱い | 撮影ごとに選べるようにする（初期値: 無視する） | C-03a |
| 3 | 同じ型のページが大量にある場合 | 撮影ごとに「全部」か「先頭N件」を選べるようにする（初期値: 全部） | C-03b |
| 4 | 画面幅の初期値 | PC 1440px／スマホ 375px。ほかの幅はあとから追加できる | S-02 |
| 5 | 比較画面の範囲 | 左右に並べる表示に加え、重ね表示（半透明・スライダー）も作る | V-05、V-05a |
| 6 | 対象サイトの規模 | 主に数十ページ | 2. 前提、5. 非機能要件 |
| 7 | JavaScriptで描画されるページ（SPA、Notionなど） | 撮影対象に含める。描画完了の待ち、ページ内スクロール領域の全体撮影、Notion用プリセットを用意する | 4.5（J-01〜J-09） |

### 撮影設定の初期値の考え方

1〜3 は撮影を始める画面で毎回選べるようにする。初期値は、数十ページ規模のサイトを撮るときに撮り漏れと重複がいちばん少なくなる組み合わせにした。

## 9. 実装の状況（2026-10-30 時点）

4章の要件は、必須・推奨・任意のすべてを実装した（M0〜M6）。詳しくは [design.md](design.md) を参照。

| 区分 | 要件 | 状況 |
|---|---|---|
| クロール | C-01〜C-11 | 実装済み |
| 撮影 | S-01〜S-08 | 実装済み |
| ログイン | L-01〜L-04 | 実装済み |
| 閲覧・比較 | V-01〜V-07 | 実装済み |
| JavaScriptで描画されるページ | J-01〜J-09 | 実装済み |

要件から変えた点・補足:

- **性能（5章）**: アクセス制限の厳しいサイト（Notion など）は、目安の対象外とした（M0 の検証結果による）
- **L-04 Basic認証**: 入力欄は「詳細設定」ではなく、撮影開始画面の「ログイン」欄に置いた。ID・パスワードは保存しないので、撮り直すときは入力し直す
- **ログイン切れ**: 起点ページがログイン画面に転送されたら警告する。警告は撮影結果に残る
- **J-08 Notion 用プリセット**: Notion のクラス名は自動生成なので、本文の領域は自動検出に任せ、ボタンは文字列で探して隠す
- **Notion の表示言語**: 撮影ごとに画面部品の言語が変わることがあり、こちらでは制御できない。比較画面で違いとして見える
- **未確認**: 実際のサイトに手でログインする操作（ログイン用ブラウザ）。自動テストでは Cookie を入れて再現した
